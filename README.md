# Fish TTS优化（drama-3 适配版）

> 短句开口说，长文发文字。直连 [Fish Audio](https://fish.audio)，支持 S2 情绪标签与 **drama-3 导演指令**，发文字时自动去标签。

- 🐟 **直连 Fish**：插件自己调用 Fish API，可走自建 Cloudflare Worker 反代，不依赖 AstrBot 的 TTS 设置
- 🎬 **drama-3 导演指令**：模型选 `drama-3` 后，方括号里可以写任意自然语言（中文也行）描述这场戏怎么演；另有 7 个成对尖括号标签只改局部几个词
- 🎙️ **音色库**：保存多个音色 ID（可写备注），随时切换，重启不丢；插件页面里点一下就能试听
- 🎭 **情绪标签**：`[happy]`、`[whispering]`、`[laughing]` 转语音时交给 Fish，发文字时自动去掉
- ✂️ **长短分流**：短回复转语音，长回复发文字；链接、代码块、Emoji、@ 自动过滤
- 🧠 **语音记忆**：记下每条语音说了什么，别人引用这条语音时告诉大模型

> **本仓库是 [zhouinzhe/astrbot_plugin_fish_tts](https://github.com/zhouinzhe/astrbot_plugin_fish_tts) v3.4.0 的二次开发分支**，在原版基础上适配 Fish Audio 的 `drama-3` 模型（MIT 许可，见 `LICENSE`）。改动清单见文末「相对上游的改动」。
>
> 原名「TTS 长短分流」（`astrbot_plugin_tts_by_length`），v3.2 起改名为 **Fish TTS优化**，插件标识和仓库改为 `astrbot_plugin_fish_tts`。
> 从旧插件换过来：设置需要重新填一次；旧的语音记录在 `data/plugin_data/astrbot_plugin_tts_by_length/`，需要的话把 `voice_memory.json` 复制到 `data/plugin_data/astrbot_plugin_fish_tts/`。

## 工作流程

```
大模型回复 ──► 过滤（链接 / 代码 / Emoji / @）──► 判断长度
                                                    │
                    ┌───────────────────────────────┴───────────────┐
                 短（≤ 上限）                                    长 / 含 @ / 失败
                    │                                               │
        带情绪标签发给 Fish 合成                          发文字（自动去掉情绪标签）
                    │
              发送语音，并记入语音记忆
```

长度按**过滤之后、去掉情绪标签之后**的文本计算，所以带链接或标签的短回复仍然会转语音。

## 快速开始

1. 插件管理 → 上传 ZIP 安装并启用。
2. 打开插件设置 → **🐟 Fish 语音合成**，填 **API Key**（[Fish 控制台](https://fish.audio/app/api-keys)创建）。走自建反代就改**接口地址**。
3. 音色：不填就是 Fish 默认音色；想用自己的音色，管理员发 `/fish音色 添加 小克 音色ID`，再 `/fish音色 切换 小克`（见下面「音色库」）。
4. **模型**保持 `s2.1-pro`（免费开发者额度选 `s2.1-pro-free`）。情绪标签需要 S2 系列模型。
5. 关闭 AstrBot 的流式输出，否则流式回复会跳过发送前钩子，TTS 不会触发。

直连 Fish 时**不需要**在 AstrBot 里启用文本转语音或选 TTS 提供商。如果同时开着 AstrBot 自带的 TTS，把它的「触发概率」设为 **0**，避免对长文本再转一遍。

> **想继续用 AstrBot 自带的 TTS 提供商**：把「语音合成方式」改成 `astrbot`。情绪标签会原样交给那个提供商，是否生效取决于它发的是不是 S2 模型。

### 从旧版升级
- **v3.3 → v3.4**：需要 AstrBot 4.26.0 及以上，直接覆盖安装即可；已保存的音色会保留（没有备注，可以在插件页面里补）。
- **v3.2 → v3.3**：直接覆盖安装即可，设置和语音记录都沿用。
- **v3.0 或更早 → v3.1 及以后**：设置改成了分组显示，v3.3 起不再自动搬运旧的平铺设置，请到设置页重新确认一遍。
- **v2.x → v3.x**：默认改为直连 Fish，**不再使用** AstrBot 里选的 TTS 提供商。需要填 API Key；或者把「语音合成方式」设为 `astrbot` 保持原样。没填 Key 时日志会提醒一次，回复保持文字。

## 环境要求
AstrBot **4.26.0 及以上**（用到了插件页面、临时内容块等新接口；更老的 AstrBot 请继续使用 v3.3）。

## 音色库
保存多个音色（名称 + 音色 ID + 备注），随时切换，不用每次进设置页改 ID。可以在**插件页面**里管理，也可以在聊天里用指令。数据存在 `data/plugin_data/astrbot_plugin_fish_tts/voice_library.json`，更新、重装插件都不会丢。

| 指令 | 说明 |
|---|---|
| `/fish音色 添加 名称 音色ID [备注]` | 保存一个音色；同名会覆盖（不写备注就沿用原来的）。音色 ID 可以直接贴音色页面地址（`https://fish.audio/m/…`）；备注不能有空格，长备注请在插件页面里写 |
| `/fish音色 列表` | 看已保存的音色，`▶` 是当前在用的 |
| `/fish音色 切换 名称` | 切换音色，下一条语音起生效；名称也可以换成列表里的序号 |
| `/fish音色 删除 名称` | 删除；删的是当前音色就回到默认音色 |
| `/fish音色 默认` | 不用音色库里的音色，改回设置页里的默认音色 |

- **添加 / 切换 / 删除 / 默认**只有管理员能用，`列表`所有人都能看。
- 名称不分大小写，不能有空格，不能是纯数字；最多存 50 个。
- 音色选择是全局的（所有聊天共用）。没选中音色库里的音色时，用设置页里的「默认音色 ID」；那个也没填就是 Fish 默认音色。
- 只在「语音合成方式」为 `fish` 时生效。

### 插件页面
在 WebUI 的插件管理里打开本插件的详情页，进入「音色库」页面（需要登录 Dashboard，所以不用再单独判断管理员）：
- 添加、编辑（改音色 ID 和备注）、删除、切换音色、改回默认音色；名称相同会覆盖，备注留空会清掉原来的备注。
- **试听**：每个音色卡片上的「试听」、表单里的「试听这个 ID」（还没保存也能试），以及「试听当前在用的音色」。试听文字可以自己写，最多 200 个字，留空用默认的一句话；试听固定用 mp3，不受「音频格式」设置影响。
- 试听会真实调用 Fish 接口，和正常合成一样计费。

## 情绪标签

### S2 系列
Fish 的 S2 模型用方括号控制语气：`[happy] 今天天气真好`、`[sad][whispering] 我想你了`、`[laughing] 哈哈 笑死我了`。

### drama-3（导演模型）
在 **🐟 Fish 语音合成 → 模型** 里选 `drama-3` 后，多出两种能力：

**1. 方括号 = 自然语言导演指令**

不用再局限于固定词表，直接描述这场戏该怎么演，中文英文都行：

```
[温柔地，像贴近对方说话] 你来啦。
[有点累了，声音低下去] 今天好长啊。
[急促，像在赶时间] 快点快点，来不及了。
```

叹气、笑声、吸气、停顿也直接写在方括号里，放在发生的位置：`[叹了口气] 算了。[轻笑] 你猜怎么着？`

**2. 成对尖括号 = 只改局部几个词**

想把某几个词的读法改一下、其余不变，用成对标签包住它们。**只有这七个**：

| 标签 | 效果 |
|---|---|
| `<whisper>…</whisper>` | 这几个词用耳语 |
| `<emphasis>…</emphasis>` | 加重强调 |
| `<soft>…</soft>` | 放轻放柔 |
| `<fast>…</fast>` | 加快 |
| `<slow>…</slow>` | 放慢 |
| `<stress>…</stress>` | 重读 |
| `<forceful>…</forceful>` | 用力、强硬 |

```
[轻声安慰] 没关系，<soft>慢慢来</soft>。
[压着火] 我说了，<stress>最后一遍</stress>。
```

**必须成对**。落单的 `<soft>` 不会报错，但效果可能作用到整段——插件检测到会在日志里警告一次。

### 标签处理规则（两套语法通用）

| 场景 | 插件怎么处理 |
|---|---|
| 转语音 | 标签原样交给 Fish（全角 `［］` 换成半角；一条最多保留设定个数） |
| 算长度 | 标签不计入字数（`[excited][laughing] 哈哈` 只算 2 个字） |
| 发文字（太长、含 @、合成失败……） | 自动去掉标签；代码块和行内代码里的不动 |
| 语音记忆、去重 | 按去掉标签的文本，`[happy] 好呀` 和 `[excited] 好呀` 算同一句 |
| 只有标签没有文字（如 `[laughing]`） | 不转语音；发文字时这条会被丢掉 |

> drama-3 的成对标签在内部会先换成占位符再走 markdown 清理，最后还原——否则 `_MD_MARK` 会把 `>` 吃掉，`<soft>` 变成 `<soft`，指令就失效了。

**让大模型写出标签**，两种办法：
1. 开 **🎭 情绪标签 → 自动给大模型加标签使用说明**：插件每次请求把下面这段追加到系统提示词末尾（固定文本，不影响提示词缓存）。**选 drama-3 时会自动换成 drama-3 版说明**，不需要你手改。
2. 手动把它贴进人设，按角色改写，比如只保留会用到的标签。

S2 版（模型不是 drama 系列时用）：

```
【语音情绪标签】你的回复可能会被转成语音。想表达语气时，可以在句子开头加一个方括号情绪标签，例如：[happy] [sad] [angry] [excited] [surprised] [nervous] [calm] [curious] [sarcastic] [whispering] [soft tone] [laughing] [sighing]。
规则：标签只用英文，放在句首，每句最多 1~2 个；[laughing]、[sighing] 这类声音标签后面要跟上对应的拟声词（如“[laughing] 哈哈”）；语气平淡的句子不加标签，不要每句话都加；不要解释标签，也不要把标签当成对话内容。
```

drama-3 版（模型选 drama-3 时自动使用）：

```
【语音导演指令】你的回复会被转成语音，朗读引擎支持「导演式」表演指令。想让声音生动，就要在方括号里写清楚这句话「该怎么发声」，而不只是写情绪。

一、指令要具体到发声
写音高、气声、语速、力度、共鸣，不要只写情绪词。
✓ [声音放轻，气声多，像贴着耳朵说话]
✓ [音调压低，尾音往下掉，有点疲惫]
✓ [语速快，呼吸急，句子之间没停顿]
✗ [温柔]、[伤心] 这类只有情绪没有发声的写法

二、必须有情绪转折，不许一条到底
整段只有一个调子是错的。一条回复里至少要有一次语气变化，通常在这些位置：
- 说到具体的回忆、承诺或责备时
- 从句号段落切到问句、感叹句时
- 先肯定后否定、话说一半又改口时

三、局部改词用成对标签
只支持这七个：<whisper> <emphasis> <soft> <fast> <slow> <stress> <forceful>
例：没关系，<soft>慢慢来</soft>。<stress>这句我说最后一遍</stress>。
必须成对写出，不要只写开标签。

四、声音和停顿直接写进方括号
叹气、笑声、吸气、停顿放在发生的位置：[叹了口气] [轻轻笑了一下] [短暂停顿]。
停顿只写方括号，不要写成 <pause>。

五、示例（同一条回复的两种写法）
差：[温柔地] 你今天回来得好晚。我做了饭，都凉了。下次能不能早点？
好：[语气轻松] 你今天回来得好晚呀。[短暂停顿][声音低下去，尾音闷闷的] 我做了饭，<slow>都凉了</slow>。[短促吸了口气，重新打起精神] 下次…能不能早点？

六、克制
每 2~3 句加一个方括号指令即可，不要每句都加；一条回复最多 3~4 个。
不要把动作描写、外貌或剧情说明当成台词念出来，也不要解释标签。
```

> **这版提示词的设计依据**：Fish Audio [drama-3 官方文档](https://docs.fish.audio/features/text-to-speech/drama-3)的示例全部具体到音高、气声、语速、力度（`[low, gravelly, tired but in control]`、`[fast, nervous, stumbling over words]`），而不是只写一个情绪词。只写「温柔」「伤心」时模型不知道该怎么变声，表现会接近平淡播报。
>
> 注意：本插件**不支持** `<pc_tts>` 之类的分段协议，写了会被原样念出来。整条回复都是朗读目标，标签只是修饰。

**哪些方括号算标签**
- `any`（默认）：任何不超过 40 字的短方括号。S2 支持自然语言描述，`[softly laughing]`、`[轻声]` 也能用；drama-3 更是完全靠自然语言指令工作。`[CQ:…]`、`[At:…]`、`[1]`、`arr[i]`、Markdown 链接不会被误判。
- `whitelist`：只认 Fish 文档里的标签，再加上你在「额外标签」里补充的。**选 drama-3 时不要用这个**，否则中文指令会被当成普通文字念出来。

**标签速查**（完整列表见 Fish 文档 [Emotion Control](https://docs.fish.audio/developer-guide/core-features/emotions)）
- 情绪：`happy sad angry excited calm nervous surprised curious sarcastic worried embarrassed grateful disappointed hopeful lonely …`
- 语气：`whispering` `soft tone` `shouting` `screaming` `in a hurry tone` `emphasis`
- 声音：`laughing` `chuckling` `sighing` `sobbing` `gasping` `yawning` `clear throat` …
- 停顿：`break` `long-break`　强度：`slightly sad` `very excited` `extremely angry`

**Fish 官方建议**：标签放句首效果最好；每句一个主情绪，叠加不超过 3 个；声音标签后面写上对应的字；短文本别滥用。

**限制**
- 智能体（Agent）用 `send_message_to_user` 等工具直接发出的消息不经过发送前钩子，里面的标签会原样显示。可以在提示词里加一句"工具发送的消息不要加情绪标签"。
- 「自定义过滤规则」里别写会匹配 `[happy]` 这类方括号的正则，否则标签在被识别前就被删了。
- `any` 模式下，大模型写的 `[注意]`、`[笑]` 这类短方括号也会当标签（发文字时被去掉）。不想这样就用 `whitelist`。
- Fish 的 S1 模型用圆括号写法 `(happy)`，且将于 2026-12-31 下线；插件只处理方括号。

## 设置一览
设置页按下面六组显示，没改过的 Fish 参数不会发给 Fish，用 Fish 自己的默认值。

### ⚙️ 基础设置
| 设置 | 默认 | 说明 |
|---|---|---|
| 启用插件 | 开 | 总开关 |
| 语音长度上限 | 80 | 超过就发文字；0 = 不限 |
| 语音长度下限 | 1 | 短于该长度不转语音 |
| 转语音概率 | 1.0 | 短文本转语音的概率 |
| TTS 超时时间 | 30 秒 | 超时自动发文字；0 = 不限时（直连 Fish 时底层最多等 120 秒） |
| 只处理大模型回复 | 开 | 关闭后指令回复等也参与判断 |
| 跳过的平台名 | 空 | 如 `webchat`，这些平台保持原样 |

### 🐟 Fish 语音合成
| 设置 | 默认 | 说明 |
|---|---|---|
| 语音合成方式 | fish | `fish` 插件直连；`astrbot` 沿用 AstrBot 的 TTS 提供商 |
| API Key | 空 | Fish API Key |
| 接口地址 | `https://api.fish.audio` | 走 Worker 反代就填反代地址（带不带 `/v1` 都行）；反代需原样转发 `Authorization` 和 `model` 请求头 |
| 默认音色 ID | 空 | 没选中音色库里的音色时用这个；音色页面地址末尾的 ID，空 = Fish 默认音色 |
| 模型 | s2.1-pro | 情绪标签需要 S2 系列；免费额度选 s2.1-pro-free |
| 音频格式 | mp3 | mp3 / wav / opus |

### 🎛️ Fish 高级参数
| 设置 | 默认 | 说明 |
|---|---|---|
| 语速 | 1.0 | 0.5~2.0；1.0 不传 |
| 音量调整 | 0 dB | 0 不传 |
| temperature / top_p | 0 | 0 = 不传，用 Fish 默认值；范围 0~1 |
| 延迟 / 质量取舍 | normal | normal 质量最好 / balanced / low 延迟最低 |
| 文本规范化 | 开 | 让 Fish 处理中英文里的数字等写法 |
| 失败重试次数 | 1 | 网络错误或 5xx（如 503 繁忙）时额外重试，0~3 |
| 额外请求参数 | 空 | 高级：JSON 对象，并入请求体（不能覆盖 `text`） |

### 🎭 情绪标签
| 设置 | 默认 | 说明 |
|---|---|---|
| 识别情绪标签 | 开 | 关闭后方括号原样处理（和 v2.x 一样） |
| 自动给大模型加标签使用说明 | 关 | 把使用说明追加到系统提示词 |
| 发文字时去掉标签 | 开 | 没转成语音时去掉标签 |
| 一条语音最多保留几个标签 | 6 | 多余的丢掉；0 = 不限 |
| 哪些方括号算标签 | any | `any` / `whitelist` |
| 额外标签 | 空 | 白名单模式下额外认可的标签，不带方括号 |
| 标签使用说明 | 见上 | 可按人设改写 |

### 🧹 朗读过滤
| 设置 | 默认 | 说明 |
|---|---|---|
| 朗读时过滤链接 | 开 | 去掉 `http(s)://`、`www.` 链接；Markdown 链接只读文字；图片整体丢弃 |
| 回复里有链接时怎么处理 | append_links | `append_links` 语音不读、链接以文字跟在后面；`strip` 链接丢掉；`send_text` 整条发文字 |
| 含代码块时不转语音 | 开 | 整条发文字；关闭后去掉代码块只读剩下的 |
| 含 @ 时不转语音 | 开 | 有 @ 组件或正文里的 `@QQ号`、`[At:…]`、`[CQ:at,…]` 时整条发文字 |
| 朗读时去掉文本形式的 @ | 开 | 关掉上一项后，保证 ID 不被读出来 |
| 朗读时去掉 Emoji 和符号 | 开 | 避免读错或报错 |
| 朗读前去掉 Markdown 符号 | 开 | `*` `` ` `` `#` `>` 等 |
| 自定义过滤规则 | 空 | 正则，匹配到的内容不朗读、不计长度，如 `（.*?）` 去掉括号动作 |
| 转语音时同时保留原文 | 关 | 语音后跟原文（不含标签），此时链接不再单独追加 |
| 同一轮对话重复的回复 | drop | `drop` 丢掉重复文字 / `keep_text` 保留文字不转语音 / `off` 不处理 |

**重复回复**：agent 先说一句话、调用工具（如选表情），工具跑完又说同一句，会转出两条语音。去重按「忽略标点、空白和情绪标签后内容相同」判断。想从源头避免，可在人设里加一句「用工具之后，最终回复不要重复已经说过的话」。

## 语音记忆是怎么工作的
**问题**：大模型自己发出的语音，对它来说只是一条没有内容的"语音消息"。有人引用这条语音时，框架传给大模型的引用内容是空的。

**做法**
1. 每次转成语音，把实际朗读的文本（**不含情绪标签**）记下来，按聊天保存。
2. 有人引用机器人的语音时，用 OneBot 的 `get_msg` 反查被引用消息的真实发送时间，对上记录，把"语音里说的是：「……」"补在这条消息后面。第一次识别成功后会记住消息 ID，之后精确命中，不再调接口。
3. 两条语音时间太近分不清时**不猜**，把候选都列出来；没有记录时明确告诉大模型"内容没有记录"，避免它编。
4. 对方提到"语音 / 声音 / 说话"等词时，会补一段"你最近发过这几条语音"。

这些补充说明作为**临时内容块**（`extra_user_content_parts` + `mark_as_temp()`）加在本轮用户消息后面：只参与这一次请求，不写进对话历史，也不改系统提示词，所以不会破坏提示词缓存。
任何一步出错都只记日志，不影响聊天和语音发送。

**怎么确认生效**：让机器人发一条语音，再引用它说句话。日志里应该有 `已转为语音`（带标签时会写"含 N 个情绪标签"）和 `引用识别：命中语音记录`。

**限制**
- 精确识别依赖 OneBot（QQ / NapCat）的 `get_msg`；其他平台只能用引用里自带的时间，未经验证。
- 升级前发的语音、别的插件或 AstrBot 内置 TTS 发的语音没有记录；只识别机器人**自己**的语音，别人发的语音需要 STT，本插件不做。
- 流式输出下发送前钩子不触发，TTS 和语音记录都不会生效。

## 群聊注意事项
- 只识别 `@数字ID`、`[At:…]`、`[CQ:at,…]` 和真正的 @ 组件；`@昵称` 没有固定边界，不会识别，需要的话用「自定义过滤规则」加正则。
- 如果 AstrBot 全局开了「回复时 @ 发送者 / 引用回复」，框架会在插件之后才加上它们，语音能否带上取决于平台。

## 排错
| 日志 / 现象 | 原因与办法 |
|---|---|
| `还没有填写 Fish API Key` | 填 Key，或把「语音合成方式」设为 `astrbot` |
| `Fish TTS 合成失败 … HTTP 401` | Key 不对；走反代时检查有没有原样转发 `Authorization` |
| `… HTTP 402` | Fish 账户余额不足 |
| `… HTTP 503` | Fish 繁忙；会按重试次数重试，仍失败就发文字 |
| `返回的不是音频` | 多半是反代 / 网关返回了错误页，日志里带响应开头；检查接口地址 |
| `Fish TTS 超过 N 秒未返回` | 网络慢或 Fish 繁忙，调大 TTS 超时时间 |
| 标签被念出来了 | 多半是模型不是 S2；检查「模型」（`astrbot` 方式下检查提供商用的模型） |
| 语音没有情绪变化 | 日志里没有"含 N 个情绪标签"：大模型没写标签，开自动加说明或把说明贴进人设 |
| 文字里出现了 `[happy]` | 这条消息没经过本插件（Agent 工具发的 / 被跳过的平台），见情绪标签的限制 |
| 文字里出现了 `<soft>` | 检查「模型」是否真的是 `drama-3`（成对标签只在 drama 系列下识别），以及「识别 drama-3 的成对尖括号标签」是否被关掉了 |
| 日志警告"未闭合的成对标签" | 大模型写了 `<soft>` 却没写 `</soft>`；drama-3 会把效果作用到整段。可在人设里强调"必须成对" |
| 选了 drama-3 但语气没变化 | `tag_mode` 被设成了 `whitelist`，中文指令不在白名单里会被当普通文字念。改回 `any` |
